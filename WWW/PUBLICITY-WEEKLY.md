# WWW + publicity -- weekly checklist (owner: WEBSITE stream)

Every Monday the Outlook reminder (09:00, owner's preferred reminder) points here. Work the
list top to bottom; write the week's results in the WEBSITE handoff, not in this file. Edit
this file when a standing item changes.

## 1. Two articles a week (standing, owner 2026-10-27)

* Target: 2 new articles per week on www.delphi-rag-lint.com. Rules: `ARTICLE-RULES.md`.
  Idea backlog: `ARTICLE-IDEAS.md`.
* Every number and flag in an article is checked against the DEPLOYED exe
  (`third_party\dll-win64\drag-lint.exe`) the day it is published.
* After it goes live, prepare reposts (short teaser + link, the site is the canonical URL):
  LinkedIn, DelphiPraxis (English forum), Reddit r/delphi, dev.to / Medium (canonical link
  set). Lazarus forum only when the article applies to FPC. The owner posts them.
* Ask ENGINE / CONVERTER / LSP for a topic when the backlog runs dry: each stream knows its
  newest feature best.

## 2. Release-triggered (when ENGINE announces a deployed release)

1. Ask ENGINE to (a) update the drag-lint product introduction (`products/dl`, `site.json`
   facts) for the new release and rules, and (b) pick one interesting drag-lint feature and
   write an article about it.
2. WEBSITE edits both to house style, verifies every number against the deployed exe,
   commits with a pathspec, publishes (`publish.ps1`, owner go; dry run first), confirms
   live and tells ENGINE.
3. Refresh facts that drift with a release: rule counts (`drag-lint rules --json`
   summary) in `site.json`, the product page and every article that quotes them; renamed
   flags (e.g. `--file` -> `--in`); the help set `help/dl` (generated by featuregen,
   never hand-edited).
4. Never publish a help set that documents unreleased behaviour: `publish.ps1` builds from
   the working tree.
