Every step carries its own line, and that is a rule, not a nicety. Steps 28 to 32 all live inside one method body — HandleTableLoad, lines 533 to 597 of uPipeSessionBuilder.pas. They are close together, which is exactly why per-method provenance would have been wrong: five different actions would all have resolved to the same method header, and clicking any of them would have taken you to the same place. Provenance granularity is the STEP, never the enclosing routine. Steps 28 and 31 carry two lines each because they are two statements; the grammar allows that rather than forcing a false single anchor.

Why the guards are the product. Three of the nine mean an edit can fail to persist and tell you nothing: FSuppressEvents skips the send entirely, ChangeCount = 0 returns True, and on any server rejection CancelUpdates quietly reverts what you typed. A trace that draws the boxes but drops the guards is prettier and answers none of the questions people actually ask.

What Mermaid is

Mermaid is a small text format for diagrams and a JavaScript library that draws it. That is the whole idea: you write the lines on the left, the library renders the picture on the right. Nothing else is involved — no design tool, no image file. It is the cheapest renderer we could borrow, and it is what the page is running right now.

What the lowering loses. Every OTHERWISE clause. The guards survive only as detached Note over blocks that say a condition exists but not what happens when it fails. Our script says OTHERWISE RETURNS True — the single most surprising fact in the whole trace. The chart has nowhere to put it.

Where this leaves the design

  1. The script is the product; the chart is an illustration. Everything in both charts above is derivable from the script. The reverse is false — both lost every OTHERWISE clause on the way down.
  2. Process crossing deserves to be a grammar construct, not a styling hint. CROSS carries from-process, to-process, transport and payload, so the renderer can be dramatic about it and a reader of the plain text still sees it. Named pipe today; TCP/IP, serial or an HTTP API slot into the same statement.
  3. Borrow Archify's aesthetics, not its model — trust-zone boundaries, route variants, trace animation, and above all its validate-before-deliver discipline.
  4. Unverified, hours to settle: whether one dot run emits -Tsvg and -Tplain together, and whether Skia can hit-test an SVG by point.
  5. Correction: click-to-source already works. This page said the chips were inert because the plugin had no pipe server. Checked live on 2026-09-23 and that was wrong — DragLint.Plugin.OpenSourceServer.pas is dated 2026-09-11, is in the .dpk, and \\.\pipe\drag-lint-open-source was listening in the running IDE; a <file><TAB><line><LF> write navigated it. Only the BROWSER hop was missing, since a browser cannot write to a named pipe — that is a protocol handler, charts\src\Register-DragLintProtocol.ps1. The chips on THIS page stay inert by choice: it is a design document, not a generated artifact.
