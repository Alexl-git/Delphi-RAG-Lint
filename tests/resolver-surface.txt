# The RESOLVE surface, for tests\autotest\run_resolver_version_guard.ps1.
#
# Format, one entry per line:
#     <repo-relative path>::<RoutineName>      a single top-level routine
#     <repo-relative path>::*                  the whole file
#     EXCLUDE <routinename>                    classified as NOT resolve, with
#                                              a reason in a comment above it
#
# WHY BY FUNCTION AND NOT BY DIRECTORY. The resolve pass straddles two trees:
# src\index\DRagLint.Index.CallResolver.pas and the writers in
# src\storage\DRagLint.Storage.SQLite.pas. No line through the directory tree
# separates "would this build PARSE differently?" from "would it DERIVE
# different edges?", which is exactly why one stamp got both wrong in opposite
# directions -- src\index over-billed a 5-hour re-parse for 19 resolve-only
# commits, src\storage under-billed 42 of them and went silently stale.
#
# DERIVED FROM WHAT EACH ROUTINE WRITES, then closed over the callees the
# autodoc `<para>Calls:</para>` facts already record. NOT from a name regex:
# the churn probe that PRICED this problem used one and says in its own source
# that it is "deliberately generous".
#
#   ResolveUnitUseTargets -> unit_uses.target_file_id
#   ResolveAncestry       -> type_ancestors
#   ResolveHelpers        -> type_helpers
#   ResolveCallTargets    -> call_edges, refs.receiver_text/external_target

# EXCLUSIONS. Each is a routine whose NAME matches the resolve vocabulary and
# which is deliberately NOT part of the surface. The guard fails on a
# vocabulary-matching routine that is in neither list, so "someone forgot"
# becomes a failure instead of silence -- but the regex only ever flags drift,
# it never defines the surface.

# Logging and timing. They are on the call list and change nothing that is
# stored. Including them would bump the stamp for a changed log line, which is
# precisely the over-billing this split exists to end.
EXCLUDE resolvelog
EXCLUDE resolvesecs

# Query-side READERS. A reader cannot make stored data stale -- it consumes the

# Reports which ancestor edges this index left unresolved, so the ANCESTRY

# Asks whether call_edges must be rebuilt; it reads state and answers, and the

# A path lookup that merely happens to be spelled Resolve*. This is the exact
# false positive a name regex produces, kept here as the worked example.

# Query-side reader for `query --name 'TList<T>'`: prefers rows of the arity the
