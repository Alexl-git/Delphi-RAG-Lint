================================================================================
 drag-lint - FEATURE OVERVIEW
 A symbol-aware retrieval + lint + refactoring + IDE-integration tool for Delphi
================================================================================

Pure Object Pascal at runtime - no Python, Node, or Rust, and no cloud AI.
Deterministic, AST-exact, offline.

Use it as:
  - CLI tool (drag-lint.exe)
  - LSP server        (Zed / VS Code / Vim / Sublime)
  - MCP server        (Claude / Cursor and other AI agents)
  - RAD Studio 13 (Florence, 37.0) design-time IDE plugin (BPL)

Built on the tree-sitter-delphi13 grammar (sibling project) plus vendored
tree-sitter grammars for DFM and Firebird SQL. Status: alpha, under active daily
development. License: MIT.

Legend for the rule lists below:
  (E) error   (W) warning   (I) info   (H) hint   (off) = ships disabled
Counts are current as of index schema v16 and the 166-rule catalog. The live,
authoritative lists are always "drag-lint rules" and "drag-lint --help".

--------------------------------------------------------------------------------
 1. INDEXING & STORAGE
--------------------------------------------------------------------------------
- One portable SQLite file per codebase (schema v16); the index is the single
  source of truth, opened read-only by every consumer. "drag-lint index" is the
  only writer.
- Indexes .pas / .dpr / .dpk / .inc via the tree-sitter delphi13 grammar; full
  symbol coverage: units, classes, interfaces, records, methods / procs /
  functions / constructors / destructors, properties, fields, enums + enum
  values, consts, initialization / finalization, and (deep mode) typed params
  and local variables.
- Incremental reindex: per-file mtime + sha256 staleness check; only changed
  files are re-parsed, then whole-DB resolve passes re-run.
- Indexing commands:
    index <path> --db F                     index a folder tree
    index --project <x.dproj>               resolve the project's real closure
    index --all [--only S] [--platform p]   build every DB in the manifest
    index --all --jobs 0                    parallel (all cores)
    index --watch [--interval N]            hot-polling reindex daemon
    index --dry-run                         preview resolved folders, no write
- Library / registry scan (no project needed): builds one library index from the
  IDE's Library and Browsing search paths read straight from the registry, with
  $(BDS) / $(Platform) macros expanded and folders deduplicated:
    index --scan-libraries-win              Win32 + Win64 (RTL/VCL/FMX + 3rd-party)
    index --scan-libraries-all              every registered platform (adds
                                            Posix / iOS / Android / OSX source)
- "library-drift" lists registry roots not yet in the index (exit 2 on drift),
  so you can tell after installing DevExpress/TMS/etc. what needs reindexing.
- Deep vs shallow indexing: deep (projects) records read/write usage refs so
  Find-Usages of variables and components works; shallow (libraries) keeps
  definitions, calls and types only.
- Named-DB manifest (drag-lint.json): "settings" + "indexes" sections map source
  roots to DBs, support per-platform DBs via {platform} templating, glob
  include/exclude, size guards, and a special "registry-libraries" source.
    resolve-dbs --platform <p>              show the DB set a query would merge
- Consumers (query / lsp / serve / graph) auto-select the right DB set from the
  manifest + platform; multi-DB queries via repeated --db.
- Workspace mode: index many projects into one shared DB (workspace add / status
  / index).
- Scan hygiene: honors .gitignore / .hgignore, a .scanignore marker, and skips
  *BACKUP* / "- Copy.pas" / *_OLD* / __history / .git / node_modules.
- Rich schema (29 tables at v16) beyond symbols/refs: unit_uses, call_edges
  (with certain/ambiguous confidence + receiver type), type_ancestors,
  type_helpers, symbol_docs, di_bindings (Spring4D), string_literals + FTS5
  shadow tables, symbol_trigrams (fuzzy), compiler_findings, Firebird snapshot
  tables, and cross-DB orm_links.
- Stability contract for external consumers: additive columns only, documented
  in docs/INDEX-SCHEMA.md; introspect any index live with:
    schema --db F --format json            schema_version + tables + row counts
- Size escape hatch: "purge-locals" drops params/locals and VACUUMs while
  keeping the resolved call graph intact (re-inflated on the next index).


--------------------------------------------------------------------------------
 2. PARSING & PREPROCESSING
--------------------------------------------------------------------------------
- tree-sitter delphi13 parser: symbols, references, unit-section stamping
  (interface vs implementation), nesting-depth tracking, and parse-error
  (ERROR / MISSING node) collection.
- tree-sitter DFM parser: component / property / event / collection / binary
  object model; decodes multi-atom DFM strings and #nn char codes to
  search-friendly text; detects binary DFM with an advisory.
- tree-sitter Firebird SQL parser: tables / columns / triggers / generators /
  views / procedures / exceptions / domains / constraints; tolerates comments,
  SET TERM, and malformed statements.
- In-process compiler-directive preprocessor (pure Delphi; no Node at runtime):
  blanks inactive {$IFDEF} / {$IF} / {$IFOPT} branches and every directive to
  spaces while PRESERVING byte offsets, so AST positions map 1:1 to the original
  source with no source map. On by default for per-config-accurate indexing
  (--no-preprocess to revert).
- Expression evaluator: or / and / not, six comparisons, defined() / declared(),
  $hex and integer literals, and CompilerVersion numeric compares.
- Include handling for {$I} / {$INCLUDE}: "off" or "defines-only" modes with
  near-search + BaseDir resolution.
- dcc-tolerance pass: rewrites dcc32-accepted-but-grammar-strict constructs
  (a missing trailing ';' on a final routine-directive group, certain array
  tails) via offset-identity replacement so the strict grammar still parses them.
- Platform define profiles: built-in defines for Win32 / Win64 (VER370,
  mswindows, cpu64bits, unicode, ...) unioned with DCC_Define values read from
  the .dproj Base + selected Config property groups.


--------------------------------------------------------------------------------
 3. CODE SEARCH & RETRIEVAL
--------------------------------------------------------------------------------
- Symbol lookup: query --name X or --qname Unit.Type.Method (kind, signature,
  section, visibility). Auto-fuzzy fallback on a miss (Levenshtein + trigram,
  length-adaptive threshold); sub-second exact, ~0.2-1.7 s fuzzy on 1.5M symbols.
- Full-text constant search: query --text "<phrase>" searches indexed STRING
  content only - messages, DFM captions, SQL exception text - never identifiers
  (FTS5 unicode61 + trigram). Flags: --any-order, --substring, --source
  pas|dfm|sql, --limit N.
- Callers: query find-callers --name X, with --context N source snippets and
  --resolved (grouped by resolved target, certain vs ambiguous).
- Doc-driven find: query find --doc-tag deprecated|since, --doc-contains,
  --no-docs, --kind, --public.
- Hierarchy / type verbs: query ancestors, query descendants, query typecat
  (float / string / class / interface / ...), helpers-of T, query hints (stored
  compiler findings by code).
- Outline / surface / slice:
    outline --file F.pas                    all symbols in a file
    surface --qname Unit.T                  the class/interface contract slice
    slice   --qname Unit.T.M                minimal reachable call-slice
    hover   --qname X                       structured doc (plain|md|json)
    typeat  F:L:C                            resolve the identifier at a position
- Grouped usages: usages --name X --width narrow|wide|very-wide (reads / writes /
  calls / type-uses / attributes / event-handlers / impact groups).
- Ranking / diffing: top --by fanin (most-depended-on symbols); diff --db old
  --db new (symbol-level public-API delta between two indexes).
- Dead code: find-deadcode (symbols with no callers outside their own unit).


--------------------------------------------------------------------------------
 4. USES & DEPENDENCIES
--------------------------------------------------------------------------------
- Unit dependency graph: graph --format dot|mermaid [--name <root>].
- Circular unit dependencies: cycles [--edges] [--causes] [--plan]
    --edges     lists each "A uses B [interface|implementation]" edge, marks
                interface edges as move-to-implementation candidates, flags
                layering inversions
    --causes    pinpoints the exact symbols/lines in A's interface forcing the
                dependency on B
    --plan      emits a followable markdown refactoring playbook (files,
                load-bearing symbols with line numbers, auto-classified fix,
                numbered steps, a verify command)
- Third-party dependency report: deps-report [--edges] [--format text|json|csv]
  - per external unit: which project units import it, count, shortest uses-path,
  and a library grouping (RTL / DevExpress / Spring4D / FireDAC / other).
- Uses cleanup, compiler-verified:
    uses-audit <unit.pas>                   propose iface->impl moves + unused
    uses-fix <unit.pas> --project <dproj>   dry-run cleanup report
    uses-fix ... --apply [--remove-unused]  apply (.bak backup)
  (Caveat, stated in the docs: per-unit verify is best-effort; always do a full
  project build after --apply.)
- Add-to-uses resolution: find-unit --name X --in F (adds the declaring unit to
  F's uses clause, section-aware, --apply); resolve-uses --name X.
- Framework wiring: wiring --qname IIntf|TForm - Spring4D DI edges (impl class +
  lifetime + resolve-sites) plus DFM event -> handler mapping; --coverage lists
  unresolved DI registrations.
- Project reconciliation: reconcile-project <App.dproj> [--apply] (sync member
  list, flag stale used units).


--------------------------------------------------------------------------------
 5. CALL GRAPH & IMPACT ANALYSIS
--------------------------------------------------------------------------------
- Resolved call edges: a call resolver types the receiver expression (method
  chains, X as T / T(X) casts) and records call_edges with certain/ambiguous
  confidence.
- Navigation verbs:
    find-callees --qname X                  outgoing resolved calls
    callgraph --qname X --direction ...     callers|callees, depth-bounded,
                                            cycle-guarded
    reverse-calltree --qname X              N-deep upward tree (unit:line per
                                            node, cycle markers; text/json/dot/
                                            mermaid)
    call-path --from A --to B               shortest resolved path
    butterfly --qname X                     callers-up + callees-down in one chart
    impact --qname X [--depth N]            transitive-caller blast radius
    ambiguous-calls / dump-call-edges       call-resolution diagnostics


--------------------------------------------------------------------------------
 6. CODE-ANALYSIS ENGINE (data-flow, CFG, clones)
--------------------------------------------------------------------------------
This is the deep static-analysis layer that backs many lint rules.
- Per-routine control-flow graph (basic blocks, synthetic Entry/Exit,
  predecessor/successor edges, for-loop-variable tracking).
- Generic monotone data-flow framework: worklist fixpoint solver with
  forward/backward lattices (Join / Transfer / Boundary / Bottom).
- Definite-assignment analysis (must + may) -> use-before-assignment.
- Liveness analysis (backward may-live) -> dead stores, overwrite-before-read,
  write-only locals.
- Double-free / dangling-pointer analysis that distinguishes raw .Free /
  .DisposeOf (leaves a dangling reference) from FreeAndNil (safe).
- Object-leak / escape analysis ("may-open": a constructor-assigned local that
  is never freed or escaped), with an ownership oracle for call arguments.
- Clone detection: Type-2 (renamed-identifier tolerant) maximal normalized-token
  runs, within-file and cross-file (Rabin-Karp token hashing).
- Class metrics (the CK suite) and routine size/complexity metrics.

Naming-convention linting (nine config-driven rules):
- A "naming" block in drag-lint-lint.json sets type prefixes (class T /
  interface I / pointer P / exception E), field prefix (F), param prefix, method
  / const / local casing (PascalCase | UPPER_CASE | camelCase), reserved-word
  casing, and minimum identifier length / Hungarian-prefix checks.
- Presets in the IDE dock: "Embarcadero" (AValue params) and "House"
  (pMyParam / FMyField / TMyClass) bulk-set the values; "Custom" is auto-shown
  when values match neither.
- Save-your-own presets: tune the values, "Save as..." names it and adds it to
  the combo (stored per-project in naming.presets[]); "Delete" removes a saved
  preset.

Lint engine capabilities:
- Per-project config drag-lint-lint.json (auto-discovered, or --config): disabled
  / enabled arrays, per-rule severity map, metric thresholds, named profiles
  (--profile), naming block, autofix list; CLI --enable / --disable compose over
  it.
- Four severity levels: error > warning > info > hint.
- Suppression: // drag-lint:ignore (whole line) or // drag-lint:ignore <rule-id>.
- CI ergonomics: --format text|json|sarif (SARIF 2.1.0 for GitHub code-scanning),
  --fail-on error|warning|info|none, and --baseline / --write-baseline
  (line-shift-stable fingerprints for "new findings only" gating).
- Autofix: --fix (dry-run) / --apply (writes, .bak backup); --fix-line and
  --fix-rule target one finding (the IDE "Fix it"); 17 rules are mechanically
  fixable (redundant-*, boolean-comparison-true, self-assignment,
  reserved-word-casing, the naming re-casing/prefix rules, doc-drift,
  missing-doc, off-by-one-count [tagged behaviour-changing]).


--------------------------------------------------------------------------------
 8. COMPILER DIAGNOSTICS (without a full build)
--------------------------------------------------------------------------------
- check-unit <unit.pas> --project <dproj> [--platform p]: compiles ONE unit in
  its real project context, so you get genuine semantic errors (e.g. E2003
  Undeclared identifier) fast.
    --shadow          compile the UNSAVED buffer via an overlay
    --resolve-uses    turn "undeclared identifier" into "add unit X to uses"
- compile-check <target>: runs dcc32 / dcc64 / msbuild out-of-process, parses
  H/W/E/F lines into structured compiler_findings (text or --json).
- refresh-findings --project X --db F [--full]: recompiles only stale units
  (>=2 stale -> full build, 1 -> incremental, 0 -> no-op) and refreshes stored
  findings, so DCC hints stay current even for clean unchanged units. Spawned by
  the IDE on save/idle and by the "Full Compile Sweep" menu.
- import-log <logfile>: ingest a saved msbuild / dcc log into the index.
- ghost-check <dproj> --overlays <manifest>: compile a project with one or more
  units' unsaved content overlaid (multi-unit), restoring every file byte-for-
  byte; powers the IDE live ghost-compile. ghost-recover restores any files left
  overlaid by a crash (recovery journal).


--------------------------------------------------------------------------------
 9. REFACTORING & CODE GENERATION
--------------------------------------------------------------------------------
- rename --kind symbol|param: index-driven cross-unit rename (interface + impl
  header + all call sites) or routine-local param rename; dry-run unless --apply;
  collision-guarded; preserves ANSI encoding and CRLF; --json.
- extract-method: data-flow / liveness-backed range extraction; refuses when the
  selection has multiple outputs or escaping control flow.
- safe-delete --name: deletes a symbol and its body only when it has zero
  references.
- create-enum-helper --qname TEnum: generates an idempotent Byte-family record
  helper (ToByte / FromByte / ToString / FromString ...); --methods,
  --tostring rtti|case; create-only-if-missing.
- generate-test --qname [--framework dunitx|dunit]: DUnitX / DUnit test scaffold.
- generate-docs --qname [--format xmldoc|pasdoc]: doc-comment stub.
- format <file>: in-place formatting via the YADF formatter (--yadf-path).
- All write operations default to dry-run and back up before writing.


--------------------------------------------------------------------------------
 10. COMPONENT CONVERSION (DFM / VCL type migration)
--------------------------------------------------------------------------------
Plan AND APPLY a component/type migration (e.g. TDBEdit -> TcxDBEdit, or any
TPersistent-rooted pair) from the REAL, AST-exact property trees of both types.
- proptree --qname X [--depth N] [--format text|json]: deep recursive property
  enumerator - own + inherited properties as flattened dotted paths, recursing
  into class-typed properties down to TPersistent (depth cap, cycle guard).
- convert-scaffold --from F --to T [--out f]: auto-drafts a valid conversion-rules
  file from both trees - concrete #link where one source matches by leaf-name +
  type, ??? for ambiguities, DROPPED notes for orphaned source props.
- convert-validate --rules f: parses and validates the rules DSL, checking #link
  / #default paths against the real property trees (catches typos blind PCRE
  cannot); exit 0 valid / 1 errors / 2 bad args.
- convert-apply --unit F.pas --rules f --db DB [--only Name1,...] [--apply]:
  rewrites all FIVE conversion surfaces for each matching .dfm instance -
    (1) .pas declaration retype
    (2) .pas uses-add
    (3) .dfm object-block re-emit (moved-depth props, events, collections,
        binaries)
    (4) .pas property/event access-site rewrite (instance-scoped)
    (5) runtime-creator retype + a "{ TODO: verify creator }" marker
- DSL: a superset of Embarcadero reFind - reFind directives verbatim (#unuse,
  #remove, #migrate, raw PCRE) plus drag-lint's #convert / #link / #default /
  #ignore / #note.
- Safety: dry-run by default; a freshness guard refuses --apply on stale or
  unindexed types; --apply writes .BCK<n> backups (never clobbers), a crash-safe
  recovery.txt written first, and an in-file marker; a hard re-emit failure skips
  the whole instance (no half-conversion). --no-backup opts out.
- Full DSL reference and the safety scheme: docs/CONVERSION-RULES.md.


--------------------------------------------------------------------------------
 11. DOCUMENTATION
--------------------------------------------------------------------------------
- DocInsight / doc-comment indexing: XMLDoc (///), PasDoc ({** *} / (** *)),
  one-line, and opt-in loose comments; ten tag types stored in symbol_docs
  (summary / remarks / returns / params / exceptions / example / seealso / since
  / deprecated).
- document --qname | --unit | --project (and document-all / AutoDocument):
  generates or repairs managed doc-comments with sentinel-fenced "facts" regions
  (Called-from / Calls / Used-in / Raises / Returns). Facts-only by default so it
  never fabricates prose; idempotent; repair mode.
- doc-drift: detects doc-vs-code staleness; a mechanically-safe subset is
  auto-fixable via --fix.
- generate-docs --qname [--format xmldoc|pasdoc]: stub generator.
- Exports: export obsidian (one .md per unit with wikilink cross-refs,
  auto-registers/launches the vault); export enums (firebird-sql / csv / json /
  delphi-const); forms-csv (one row per form with its click-path from the main
  form, "Called From", captions - a tester navigation map).


--------------------------------------------------------------------------------
 12. SQL & FIREBIRD SUPPORT
--------------------------------------------------------------------------------
- SQL DDL indexing (Firebird): tables / columns / triggers / generators / views /
  procedures / exceptions / domains / constraints from .sql files (MS*.SQL by
  default; --no-sql-ms to index every .sql). CREATE EXCEPTION message text is
  FTS-searchable.
- fb-snapshot: live Firebird metadata pull over FireDAC - RDB$RELATIONS /
  RELATION_FIELDS plus application FIB$ tables (field UI info, dataset CRUD-SQL
  templates, enum code->label). Each row is snapshot-stamped so multiple
  snapshots coexist and can be diffed; gracefully skips absent tables.
- link-orm: Delphi <-> SQL ORM linker by naming convention (T<X>/I<X> -> table X,
  F<Y> -> column Y) with confidence scores; multi-DB; writes orm_links for
  cross-DB graphs.


--------------------------------------------------------------------------------
 13. AI COLLABORATION
--------------------------------------------------------------------------------
drag-lint is built to be driven by an AI coding agent and to feed it precise,
low-token context instead of whole files.
- MCP server (serve --db): a JSON-RPC 2.0 stdio server exposing ~15 typed tools
  to Claude / Cursor and other agents (see section 15).
- Context bundles: context --task "modify Unit.T.Method" --format markdown emits
  a compact bundle (doc + class surface + the target's own body + capped
  callers) that is MEASURED ~10-60x leaner than opening the source units (an ORM3
  example: ~556 vs ~33,762 tokens). Task verbs: modify / inspect / refactor /
  delete / extend. Lean by default (auto-generated DFM component fields stripped);
  --full-surface only for form/DFM work. bench-context measures the savings.
- Two agent access modes, same engine: the CLI (most token-efficient - no
  resident tool schema) and MCP (structured tools whose schemas stay resident).
  Nearly every verb supports --json.
- Deterministic, zero-hallucination retrieval: answers "where exactly in our
  code is X / who calls it / what implements it" from the AST-exact index (no
  string-literal, comment, or backup-copy noise), so an agent grounds edits in
  real symbols instead of guessing.
- AI-oriented codegen an agent can call: generate-docs, generate-test,
  rename_symbol, run_compile_check, run_ast_checks.
- Copy-paste agent guides: docs/AI-USAGE.md (drive drag-lint over CLI or MCP),
  docs/AI-INDEX-FIRST.md (query the index before reading files), and
  docs/AI-CONVERT-RUNBOOK.md (agent-run component conversion).

--------------------------------------------------------------------------------
 18. ARCHITECTURE
--------------------------------------------------------------------------------
  drag-lint.exe
    |
    +-- CLI dispatch
    |     +-- Indexer  -> tree-sitter-delphi13.dll (Delphi 13 grammar)
    |     |             -> tree-sitter-dfm.dll      (DFM grammar)
    |     |             -> tree-sitter-sql          (Firebird DDL)
    |     |             -> tree-sitter.dll          (libtree-sitter runtime)
    |     |             -> SQLite storage
    |     +-- Query / Surface / Impact / Slice / Context
    |     +-- Lint (built-in checks + .scm rule runner + data-flow engine)
    |     +-- Refactor (rename, extract, doc/test gen, YADF format, convert)
    |     +-- Compiler diagnostics (dcc / msbuild integration)
    |     +-- Workspace (multi-project shared DB)
    |
    +-- LSP server (stdio JSON-RPC)
    +-- MCP server (stdio JSON-RPC)
    +-- Context bundler

  dclDragLintWizard.bpl (RAD Studio design-time plugin)
    +-- Wizard / menu / keystrokes / EditView notifier
    +-- LSP client -> drag-lint.exe lsp
    +-- Diagnostic + code-lens caches -> in-editor markers / hover / [N callers]
    +-- Structure / Usages / Symbol-Search / Lint-Options / Graph docks
    +-- Options (INTAAddInOptions: General / Indexer / Linter / Editor)

All three entry points (CLI, LSP, MCP) call the SAME indexer, query, lint and
refactor engine. The IDE plugin is a thin wrapper over the LSP client plus direct
CLI calls for features the protocol does not cover. Dual-target build: Win32 for
the IDE plugin, Win64 for the CLI / LSP / MCP engine (Win64 handles the large
library indexes that OOM a 32-bit process).
