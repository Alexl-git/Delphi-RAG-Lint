### FTS5 reindex crash -- FULLY RESOLVED (v0.59.5-alpha)

Reindex from the IDE no longer crashes with "no such module: fts5". Confirmed clean:
`Done. Files: 335, Symbols: 23308, Refs: 115592, skipped 335 up-to-date, 3.73s`

**Root cause (final):** `FQUpsertFile` used `INSERT OR REPLACE`. REPLACE deletes the
old `files` row, which cascades via `ON DELETE CASCADE` to `string_literals`, firing
the FTS5 sync trigger inside SQLite -- bypassing all `FFts5Available` guards (those
guard method calls, not SQLite-level triggers). Win32 sqlite3.dll also lacks FTS5.

**Fix (`DRagLint.Storage.SQLite.pas`):**
- `FQUpsertFile` repurposed: `UPDATE files SET ... WHERE path=:path` (in-place, no DELETE)
- `FQInsertFile` repurposed: `INSERT OR IGNORE` fallback when `RowsAffected = 0`
- No `ON CONFLICT DO UPDATE` (Win32 Embarcadero sqlite3.dll predates SQLite 3.24)
- Diagnostics in `Migrate`: probe prints AVAILABLE/UNAVAILABLE, DROP TRIGGERs verbose,
  trigger count before + after DROP

**Architecture gotcha (permanent):**
Plugin (Win32 BPL) spawns `third_party\dll-win32\drag-lint.exe` -- NOT dll-win64.
Win32 Embarcadero sqlite3.dll is OLDER than Win64; lacks FTS5 and ON CONFLICT syntax.
Always build and deploy BOTH Win32 and Win64 after any storage layer changes.

## Gotchas

- **Win32 vs Win64 CLI**: Plugin ALWAYS spawns `dll-win32\drag-lint.exe`. Win32 sqlite3.dll
  is an OLDER build -- lacks FTS5, rejects ON CONFLICT DO UPDATE syntax. Always deploy both.
- **Build BPL**: use `delphi-build` skill (`dclDragLintWizard.dproj`, Debug/Win32).
  Close IDE before building BPL (output file locked otherwise).
- **CRLF**: Edit tool emits LF; normalize `.pas` files to CRLF + 7-bit ASCII after edits.
- **Reindex lock**: if reindex fails "used by another process", kill orphaned
  `drag-lint.exe` / `drag_lint_graph.exe` processes first.
- **fts5 in test harness**: Win32+Win64 Embarcadero sqlite3.dll lack FTS5.
  Text-search (query --text) is disabled when indexed by either CLI.
  Tests that exercise FTS5 paths will fail unless a custom FTS5-enabled sqlite3.dll is used.
