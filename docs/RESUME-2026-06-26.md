## What changed this session (2026-06-26, uncommitted)

### 1. Win32 tree-sitter DLL architecture fix

**Problem:** `third_party\dll-win32\tree-sitter*.dll` were accidentally replaced with x64
copies on 2026-06-17. All drag-lint.exe invocations from the IDE were failing with
exit code 0xC000007B (STATUS_INVALID_IMAGE_FORMAT -- DLL arch mismatch) before they
could even write to stdout, causing "LSP initialize handshake failed" in the IDE plugin.

**Fix applied:** Copied correct x86 versions from `third_party\dll\` back to `dll-win32\`:
- `tree-sitter.dll` (155136 bytes, x86)
- `tree-sitter-delphi13.dll` (2539520 bytes, x86)
- `tree-sitter-dfm.dll` (20992 bytes, x86)
Verified: `dll-win32\drag-lint.exe --version` now returns `drag-lint 0.59.5-alpha`.

**Dirty in git:** `third_party/dll-win32/tree-sitter*.dll` (3 binary files)

### 2. deploy-staged.bat: tree-sitter DLL guard added

After the BPL+exe copy, the script now also copies all 3 tree-sitter DLLs from
`third_party\dll\` (canonical x86 source) into `dll-win32\`. Prevents silent
architecture drift if someone copies from dll-win64 by mistake again.

**Dirty in git:** `deploy-staged.bat`

### 3. EnsureLspClient: always prefer Win64 drag-lint.exe

**Background:** The BPL is always 32-bit (IDE is 32-bit Win32 process). But a 32-bit
process can freely spawn a 64-bit child via CreateProcess -- only LoadLibrary is
arch-constrained. The Win64 drag-lint.exe handles large DBs better and already has
its own correct x64 tree-sitter DLLs next to it in dll-win64\. This eliminates the
need for Win32 tree-sitter DLLs in dll-win32 permanently.

**Change in `src\delphi-plugin\DragLint.Plugin.Editor.pas`:**
- `EnsureLspClient` now looks for `dll-win64\drag-lint.exe` as a sibling of the BPL dir
  (path: `ExtractFilePath(ExcludeTrailingPathDelimiter(BplDir)) + 'dll-win64\drag-lint.exe'`)
- Falls back to `BplDir + 'drag-lint.exe'` (same folder as BPL) if Win64 not found
- Falls back to PATH lookup as last resort

**Dirty in git:** `src/delphi-plugin/DragLint.Plugin.Editor.pas`

**NOTE:** After committing, rebuild the BPL and deploy it before testing. The change
is in the plugin Pascal code, so the BPL must be recompiled.
