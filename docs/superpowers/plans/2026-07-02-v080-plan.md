## Phase 2 -- store-backed refactoring signals (MISSING-FEATURES #14 batch)

**Task 2 (SCOUT FIRST -- read-only, dispatch an Explore agent).** Before implementing the coupling rules, map what
the store can attribute about a method's member/field accesses and cross-class references: can we tell, for a method
body, which OTHER class's fields/methods it touches (needed for `feature-envy` and `middle-man`)? Given refs are
name-based, quantify the signal quality. Read `ClassMetrics.pas` `ComputeCBO`/`ComputeRFC` (they already resolve
`type_use`/`call` refs per class) and `ProjectRules.pas` (god-class/unused-member patterns) as precedent. Output: a
concrete feasibility verdict per rule + the exact store calls to use. **feature-envy is the hard one -- if the scout
says the name-based signal is too weak for acceptable FP, DEFER feature-envy to v0.81 and document it.**

Then implement each as a store rule (in `ClassMetrics.pas` or `ProjectRules.pas`, per the scout), category
`refactoring` (or `metrics` for the coupling ones -- controller's call at design time), with a `tests/lint-store/<rule>/`
fixture (mode `lint-all`) and `src/` FP-sanity -> ON if clean else OFF. Order easiest-first:

- **Task 3 -- `mutable-global-variable`** (Global Data; generalize `global-form-variable`). A writable unit-level
  global `var` (not a const, not a typed-const marked as read-only). Mostly pure-AST (unit `var` section). Likely
  `info`; FP-sanity (globals are common in legacy code -> maybe OFF-by-default). Fixture + sanity.
- **Task 4 -- `middle-man`** (Remove Middle Man). A class where a high fraction (e.g. > 0.5, thresholded) of its
  methods are pure one-line delegations to the same field/object (`Result := FDelegate.X(...)` / `FDelegate.X`).
  Detect per class via AST re-walk of method bodies (like LCOM4) or refs; require >= N methods to avoid tiny-class
  noise. `info`, threshold(s). Fixture + sanity.
- **Task 5 -- `repeated-type-switch`** (Replace Conditional with Polymorphism). The same enum/type-code `case`
  selector text appearing as a `case` in >= N distinct methods (a polymorphism candidate). Collect case-selector
  texts across methods (project-wide), group, flag groups >= threshold. `info`. Fixture + sanity.
- **Task 6 -- `feature-envy`** (Move Function) -- ONLY if Task 2 scout says feasible. A method that references another
  single class's members more than its own class's. Store/AST, name-based -> FP-prone -> likely OFF-by-default or
  deferred. Fixture + heavy sanity, or DEFER with a documented note.

Each task: implement -> build -> the new `tests/lint-store/<rule>/` fixture passes + full store/file/catalog harnesses green -> `src/` FP-sanity reported -> two-stage review -> commit.
